# RUSTSEC-2026-0459: bundled SQLCipher SQLite before 3.54

Accepted until 2026-12-09 by dmytro-yevs.

SQLite before 3.54.0 can return uninitialized page-cache memory when a database
is opened together with a sibling `-wal` file whose page size differs. The
attacker must place both files where the victim process opens them.

No released `libsqlite3-sys` fixes the `bundled-sqlcipher` build: 0.39.1 pins
`sqlcipher-src` 419.0.6 (SQLite 3.53.4). SQLCipher 4.20.0 (SQLite 3.54.1) is
published as `sqlcipher-src` 420.0.0 but no `libsqlite3-sys` release uses it.

CopyPaste is not exposed:

- The history database and its `-wal` live in the owner-only application data
  directory; only the same user can replace them.
- Encrypted restore copies only the selected backup file into a private staged
  file next to the history database and opens that copy, so a `-wal` placed
  beside an untrusted backup is never read.
- Database pages and WAL frames are SQLCipher-encrypted with the device key, so
  a crafted file pair without that key fails to decrypt.

Remove this exception and upgrade `rusqlite` once a `libsqlite3-sys` release
bundles SQLCipher with SQLite 3.54.0 or later.
